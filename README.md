# Mouse Manager

> Переназначение боковых кнопок физической мыши на системные действия. Без root.

Android-приложение для планшета: служба доступности перехватывает клавиатурные события,
которые приходят от мыши, и решает, превратить ли их в системное действие или пропустить
дальше без изменений.

## Статус

| Веха | Состояние |
|---|---|
| **M1 — скелет приложения** | **Принята на устройстве 2026-11-13**: 13 PASS, 1 SKIP (физическая клавиатура), 0 FAIL |
| **M2 — ядро ремапа и именованные профили** | Запланирована, не начата |

На момент M1 приложение собирается, запускается, показывает четыре экрана, подключает
службу и ведёт журнал событий. Ремап ещё не реализован: `RemapEngine` — заглушка, которая
всегда возвращает `Pass(DISARMED)`, поэтому клавиши не поглощаются.

Дорожная карта и критерии приёмки — [`docs/ROADMAP.md`](docs/ROADMAP.md).

## Принцип работы

1. Продуктовая служба `MouseManagerService` объявляет `AccessibilityService` с
   `FLAG_REQUEST_FILTER_KEY_EVENTS` и получает клавиатурные события до приложений.
2. Боковые кнопки тестируемой мыши приходят как аккорд `Ctrl+C` / `Ctrl+V` от самого
   устройства мыши, а не как `BUTTON_BACK` / `BUTTON_FORWARD`. Это измеренный факт, а не
   предположение.
3. Устройство-источник определяется по `InputDevice.getDescriptor()`, а не по `deviceId`
   или имени: `deviceId` меняется при каждом переподключении.
4. Перехват обязан быть fail-safe: нет конфигурации, ошибка чтения или служба не
   подключена — событие не поглощается.

Подробное описание реализации и инвариантов — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Ограничения

- **Android 10 и выше** (`minSdk 29`): нужен `InputDevice.getDescriptor()`.
- **Действия «вперёд» нет** и в v1 не планируется; в интерфейсе оно не обещается.
- **Совместимость ограничена проверенными устройствами.** Поведение боковых кнопок
  зависит от прошивки мыши, поэтому на других моделях результат может отличаться.
- Тестовое устройство: **Xiaomi Pad 6 Pro**, Android 15 / API 35, HyperOS 3.
- Перехват включается только для устройств, явно выбранных в настройках; клавиши
  остальных устройств не поглощаются.

## Разрешения и приватность

- Манифест не запрашивает разрешений (`uses-permission` отсутствует), в том числе
  `INTERNET`: сетевой доступ приложению не нужен.
- `android:allowBackup="false"` — резервное копирование данных приложения отключено.
- Настройки хранятся локально в `DataStore`.
- Единственная системная возможность — служба доступности; она включается вручную в
  настройках Android.

## Сборка

Требования: JDK 17, Android SDK 36 (build-tools 36.1.0), Gradle wrapper 8.14.6 — уже в
репозитории.

```powershell
# debug-сборка
.\gradlew.bat :app:assembleDebug --no-daemon --console=plain

# JVM-тесты (61 тест в 9 suites по состоянию на S7)
.\gradlew.bat :app:testDebugUnitTest --no-daemon --console=plain
```

APK: `app\build\outputs\apk\debug\app-debug.apk`.

Спайки `spikes/s1` и `spikes/s2` собираются отдельно, каждый из своего каталога; в
корневую сборку они не входят.

## Установка и включение службы

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

1. Откройте приложение.
2. Android: **Настройки → Специальные возможности → Mouse Manager** и включите службу.
3. На экране **Устройства** выберите мышь, кнопки которой нужно перехватывать.

## Предупреждение

Приложение перехватывает клавиатурные события через службу доступности. Это системная
возможность с широкими правами: включайте её осознанно и только на устройстве, которому
доверяете. Приложение не заменяет системные средства доступности и не предназначено для
скрытого наблюдения за вводом.
