# SPIKES — доказательная база S1 и S2

> Замороженный архив экспериментов. Читать при вопросах «откуда мы это знаем» и при
> подготовке S3. Состояние продукта — `PROJECT_STATUS.md`, решения — `DECISIONS.md`.
> Ничего здесь не перепроверять на устройстве без причины.

## 1. Что где лежит

| Спайк | Каталог | Пакет | Назначение |
|---|---|---|---|
| S1 | `spikes/s1/` | `com.mousemanager.diagnostics` | диагностика ввода: события, источники, `deviceId`, `descriptor`, `scanCode`, `metaState` |
| S2 | `spikes/s2/` | `com.mousemanager.spike.s2` | фильтр клавиш: только PASS/DROP, без ремапа |

Оба — самостоятельные Gradle-проекты (свой `settings.gradle.kts` и wrapper), в корневую
сборку не входят. Собираются из своего каталога той же командой, что и продукт.

## 2. Что доказал S1

| Наблюдение | Вывод |
|---|---|
| `InputDevice.sources` нельзя проверять «по вхождению бита» | маску сравнивать точно: `sources and SOURCE_MOUSE == SOURCE_MOUSE`, с учётом комбинированных источников |
| Виртуальный тачпад приходил отдельным устройством | фильтровать по шине/виртуальности, иначе журнал забивается мусором |
| Устройства появляются и исчезают | опрос раз в 3 с; в продукте — `InputManager.InputDeviceListener` (D-015) |

Главное:

- Боковые кнопки VXE R1SE+ **не** приходят как `BUTTON_BACK` / `BUTTON_FORWARD` — вообще.
- Они приходят как **клавиатурный аккорд** `Ctrl+C` / `Ctrl+V` от устройства мыши.
- Левая/правая/средняя — `ACTION_BUTTON_PRESS/RELEASE` с `BUTTON_PRIMARY` / `SECONDARY` / `TERTIARY`.

## 3. Что доказал S2

Все 7 условий приёмки приняты на устройстве:

| № | Условие | Доказательство |
|---|---|---|
| 1 | Отдельный проект, S1 не изменён | `spike-s2\` со своим wrapper; файлы S1 не менялись |
| 2 | `canRequestFilterKeyEvents` работает | `onServiceConnected flags=0x20 filterRequested=true` |
| 3 | `descriptor` стабилен при переподключении | `ce5035b0…3992` при `deviceId` 29 → 30 → 31 |
| 4 | Перехват `Ctrl+C` / `Ctrl+V` | 12 событий `CONSUMED` (3 аккорда × 4 события) |
| 5 | Клавиатура и кнопки не ломаются | `VOLUME_UP/DOWN` от `gpio-keys` и `pmic_resin` прошли, громкость 0 → 10 |
| 6 | Без полноценного ремапа | только PASS/DROP, `ChordPolicy = {CtrlLeft, CtrlRight, C, V}` |
| 7 | Простое отключение | тумблер → `PASSED_DISARMED`; перехват не переживает перезапуск |

> В продукте строже: `armed` не хранится и сбрасывается при каждом старте процесса и
> подключении службы (D-006).

Дополнительно:

- **`adb shell input` невидим фильтру** — `onKeyEvent` не вызывается; автотесты перехвата
  через adb невозможны, только живая мышь.
- **`deviceId` — не идентификатор**: за сессию 29, 30, 31 при неизменном `descriptor`.
- **Аккорд атомарный**: `Ctrl↓ C↓ Ctrl↑ C↑` за ~120–180 мс, долгого удержания нет.
- **Средняя кнопка — не клавиша**: `ACTION_BUTTON_PRESS` + `BUTTON_TERTIARY`, мимо `onKeyEvent`.
- **`isAccessibilityTool="false"` не мешает**: HyperOS 3 включил службу без «ограниченных
  настроек» (установка через adb, installer = null).

## 4. Измерения (не перепроверять)

| Величина | Значение |
|---|---|
| Мышь | `VXE R1SE+ Mouse` |
| `descriptor` мыши | `ce5035b0dc81cc3d25dbb6f30e5e51d03dcb3992` |
| История `deviceId` | 19 → 25 → 26/27 → 29 → 30 → 31 (разные сессии) |
| Scan-коды аккорда | 29 = `KEYCODE_CTRL_LEFT`, 46 = `KEYCODE_C`, 47 = `KEYCODE_V` |
| `metaState` DOWN / UP | `0x3000` (`META_CTRL_ON | META_CTRL_LEFT_ON`) / `0x0` |
| Порядок и длительность | `Ctrl↓` → `C/V↓` → `Ctrl↑` → `C/V↑`, ~120–180 мс |
| Флаги службы | `0x20` = `FLAG_REQUEST_FILTER_KEY_EVENTS` |
| `gpio-keys` / `pmic_resin` descriptor | `485d69228e24…` / `653e1ca6257f…` |

## 5. Имена вердиктов: S2 ≠ продукт

В S2 код печатает `PASSED_OTHER_DEVICE`; в продукте по D-017 — `PASSED_FOREIGN_DEVICE`
(«событие от чужого устройства»). S2 заморожен и не переименовывается: при чтении
логов S2 это одно и то же.

payload идентичен (132 записи) — разница только в мёртвом padding инкрементальной сборки
(D-023). Побайтовое совпадение debug-APK корректно только при одинаковом пути сборки;
критерий приёмки — успешная сборка.
