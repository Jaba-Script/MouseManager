# WORKFLOW — OpenCode для Mouse Manager

Цель: минимум токенов на сессию при сохранении качества. Долговременная память — файлы,
кратковременная — контекст сессии. Всё, что должно пережить `/clear`, живёт в `docs/`.

## 1. Память

| Уровень | Где | Когда читается |
|---|---|---|
| Постоянный | `AGENTS.md` | автоматически в каждой сессии |
| Состояние | `docs/PROJECT_STATUS.md` | в начале задачи |
| Решения | `docs/DECISIONS.md` | когда задача меняет поведение |
| План | `docs/ROADMAP.md` | при выборе вехи |
| Доказательства | `docs/SPIKES.md` | при вопросах про измерения |
| Код | `app/`, `spikes/` | точечно, по конкретным файлам |

Правило: **если факт важен, он должен быть в `docs/`, а не в истории чата.**

## 2. Одна сессия = одна задача

Плохо: «Сделай ремап, профили, диагностику и почини сборку».

Хорошо: «M2, шаг 3: реализуй `ChordTracker` и `RemapEngine` по `ARCHITECTURE.md` §6.
Файлы: `core/ChordTracker.kt`, `core/RemapEngine.kt`, `core/Verdict.kt`.
Приёмка: unit-тесты §16.1 проходят. Ничего не устанавливать.»

Сессия заканчивается, когда задача принята. Следующая задача — новый контекст.

## 3. Когда `/clear`

- началась новая задача, даже если тема «та же»;
- контекст перевалил за ~50%;
- агент путается в файлах или повторяет отменённые решения;
- переход между вехами (M1 → M2).

После `/clear`: `AGENTS.md` (авто) → `PROJECT_STATUS.md` → нужный раздел
`ARCHITECTURE.md` / `DECISIONS.md`. Спайки не читать, сборку «на всякий случай» не гонять.

## 4. Когда `/compact`

- **только между задачами**, не в середине реализации или отладки;
- после компакта перечитать `AGENTS.md` + `PROJECT_STATUS.md` — это и есть восстановление
  памяти, остальное восстанавливать не нужно.

## 5. Шаблон запроса

```text
Веха: M2, шаг 3.
Цель: <одно предложение>.
Файлы: <точные пути>.
Ограничения: <что нельзя трогать>.
Приёмка: <проверяемый критерий>.
Не делать: <сборка/установка/спайки, если не нужно>.
```

Чем точнее файлы и критерий, тем меньше агент исследует и тем меньше токенов тратит.

## 6. Экономия

- указывать конкретные файлы, а не «разберись в проекте»;
- `grep`/`glob` вместо чтения дерева; большие файлы — нужным диапазоном;
- не читать `spikes/`, `build/`, `.gradle/`, `*.apk` без нужды;
- логи фильтровать (`logcat -d -s MouseManager:D | Select-Object -Last 20`); успешная
  сборка — одна строка; скриншот — только для визуальной проверки;
- для разведки — субагент `explore`: вернёт выжимку, не засоряя основной контекст;
- ссылаться на `git diff` / `git log --oneline`, а не пересказывать изменения;
- commit после каждой принятой вехи: `M1: skeleton`, `M2: chord tracker`;
- перед реорганизацией — commit (страховка).

## 7. Бюджет

| Задача | Ожидаемый контекст |
|---|---|
| Мелкая правка (1–2 файла) | 10–20% |
| Шаг вехи (3–5 файлов + тесты) | 30–50% |
| Разведка + план | 30–40%, затем `/clear` |
| Отладка на устройстве | 40–60%, лог фильтровать |

Если контекст выше 60% — заканчивать задачу, обновлять `PROJECT_STATUS`, `/clear`.

## 8. Антипаттерны

| Антипаттерн | Почему дорого |
|---|---|
| «Посмотри весь проект и предложи улучшения» | агент читает всё дерево |
| «Собери и установи, проверь» без конкретики | полный цикл сборки + логи + скриншоты |
| Архитектурное обсуждение внутри сессии реализации | контекст занят историей, а не кодом |
| `/compact` в середине отладки | теряются точные значения |
| Хранить решения только в чате | после `/clear` их нет |
| Читать спайки «для контекста» | десятки файлов, польза нулевая |
| Возвращаться к отменённым вариантам | повторный анализ заново |

## 9. Роли документов

| Документ | Не должен содержать |
|---|---|
| `AGENTS.md` | историю, детали реализации |
| `PROJECT_STATUS.md` | планы (только «следующий шаг») |
| `ARCHITECTURE.md` | даты, журнал изменений |
| `DECISIONS.md` | инструкции «как писать код» |
| `ROADMAP.md` | текущее состояние |
| `SPIKES.md` | состояние продукта, планы |

Дублирование между документами — главный источник рассинхронизации и лишних токенов.

## 10. Цикл вехи

`/clear` → `PROJECT_STATUS` + раздел `ROADMAP` → задача = один шаг → правки → сборка и
тесты → ручной чек-лист (если нужен) → обновить `PROJECT_STATUS` (+ D-0NN) → commit →
`/clear`.
